# AutoJs6 Studio · 控件拾取器实现方案

> 目标：连着真机时，把屏幕上的控件一键变成积木参数，而不是靠猜文本、试坐标。
> 适用版本：当前工程（`js/` 下的可视化 IDE）+ AutoJs6 MCP Server 1.3.0。

## 1. 目标与边界

**要做**

- 三种拾取方式：控件树点选、截图叠层点选、截图上直接取坐标。
- 拾到的结果写回积木的参数（定位方式 + 定位值，或 x/y 坐标），保证「一次拾取、代码立刻正确」。
- 对每个拾取结果做**唯一性校验**和**稳定性评分**，不稳定时明确提示，而不是悄悄写入一个下次就失效的选择器。

**不做**

- 不做 Android 系统级悬浮窗（那需要另一个 App 和 `TYPE_APPLICATION_OVERLAY` 权限）；拾取界面放在 Studio 自己的面板里。
- 不做纯图像识别的拾取（截图里找按钮）。H5 页面没有无障碍节点时，只兜底到「坐标 + 截图」，不宣称能拿到语义。
- 不改变离线/模拟器行为：拾取器只在真机连接时可用，模拟器里按钮置灰并说明原因。

## 2. 已有能力（实测，不用自造协议）

MCP 侧已经有一整套界面工具，拾取器本质是**编排这五个工具 + 选择器合成 + 回填**：

| 工具 | 用途 | 实测要点 |
| --- | --- | --- |
| `ui_dump` | 取当前窗口控件树 | `format=text/json/xml`，`maxDepth≤32`，`maxNodes≤400`，`visibleOnly`；text 带 `#n` 引用，json 不带 |
| `ui_find` | 按条件查节点 | 返回 `bounds`、`center`、以及**用来钉住该节点的 selector**；`count` 可判唯一性 |
| `ui_explain_selector` | 解释选择器为什么匹配不到 | 逐条件累计命中数、第一个失败条件、近似命中 |
| `screen_capture` | 截图 | `annotate=true` 会把最近一次 dump 的 `#n` 画到图上；30 次/分钟限流 |
| `ui_click` | 点击 | 支持 `nodeRef`（`#n`）/ `selector` / `x,y`；窗口变化会返回 `NODE_REF_STALE` |

实测样本（京东领券中心页，1080×2376）：

```
window: com.jingdong.app.mall/com.jd.lib.ttt.page.TTTMultiPageActivity  bounds=[0,0][1080,2376]  nodes=10  truncated=true
#n1 FrameLayout [0,0][1080,2376]
#n5     LinearLayout id=com.jingdong.app.mall:id/layout_main [0,0][1080,2328]
#n7       RelativeLayout c=(540,1164)
```

`ui_dump format=json` 的节点字段（可直接做渲染和数据模型）：

```json
{"depth":4,"index":0,"childCount":1,"visible":true,"className":"android.widget.LinearLayout",
 "text":"","desc":"","id":"com.jingdong.app.mall:id/layout_main",
 "bounds":{"left":0,"top":0,"right":1080,"bottom":2328},"center":[540,1164],
 "clickable":false,"enabled":true,"longClickable":false,"scrollable":false,
 "checkable":false,"checked":false,"editable":false,"focused":false,"selected":false}
```

`ui_find` 的返回里，节点自带 `selector`，但它**是用 bounds 钉的**：

```json
{"className":"android.view.View","desc":"分享得红包",
 "selector":{"className":"android.view.View","desc":"分享得红包",
             "boundsInside":{...},"boundsContains":{...}}}
```

结论：MCP 的自动 selector 适合「此刻点一下」，**不适合写进脚本**——写进脚本要换成 `id` / `text` 这类稳定条件。这正是拾取器里「选择器合成」要解决的事。

可用的选择器条件（工具报错里给出的全集）：
`text` `textContains` `textMatches` `desc` `descContains` `descMatches` `id` `idMatches` `className` `classNameMatches` `clickable` `enabled` `scrollable` `depth` `boundsInside` `boundsContains`

## 3. 总体架构与数据流

```
┌────────────── 真机 ──────────────┐        ┌──────── 浏览器（Studio）────────┐
│ AutoJs6 无障碍服务               │        │ picker.js                       │
│  └ MCP Server ─ ui_dump/ui_find ─┼──HTTP──▶ bridge.js ─ 采集层               │
│      ui_explain/screen_capture   │        │      │                          │
└─────────────────────────────────┘        │      ▼                          │
                                            │  节点模型（扁平 + 父子索引）    │
                                            │      ▼                          │
                                            │  拾取面板（树 / 截图叠层）      │
                                            │      ▼                          │
                                            │  选择器合成 + 唯一性校验        │
                                            │      ▼                          │
                                            │  回填 editor.js → 积木参数      │
                                            └─────────────────────────────────┘
```

三层职责：

1. **采集层（bridge）**：只负责发请求、拿原始结果、统一错误码；不做业务判断。
2. **拾取层（picker）**：解析节点、渲染、候选合成、校验、评分；纯逻辑，可在 Node 里单测。
3. **回填层（editor）**：把结果写进指定积木的指定参数，写入前 `snapshot()` 保证可撤销。

## 4. 节点数据模型

统一成一种结构，屏蔽 text/json 差异：

```js
{
  ref: '#n12',        // 仅 text 来源有，用于 ui_click / 截图标注
  depth: 3,
  index: 2,           // 同级序号，配合 depth 还原树
  className: 'android.widget.TextView',
  text: '更多任务',
  desc: '更多任务',
  id: 'com.jingdong.app.mall:id/coupon-left-entry',
  bounds: {left, top, right, bottom},   // 设备像素
  center: [x, y],
  flags: {clickable, enabled, scrollable, editable, visible, longClickable},
  childCount: 0
}
```

两个来源怎么选：

- **默认 `format=text`**：带 `#n`，能直接 `ui_click`，缩进就是层级；解析用正则，一行一条，容错好。
- **需要精确 bounds 或做叠层**时用 `format=json`：字段全，但没有 `#n`，点击只能走 selector。

> 取舍：一次拾取只请求一种格式，避免双倍开销；面板提供「切换为 JSON 视图」按钮按需补取。

## 5. 三种拾取模式

### A. 控件树点选（默认，最可靠）

- 打开面板 → `ui_dump` 一次 → 左树右详情。
- 树按 `depth` 缩进，节点显示 `className 文本/desc`，可折叠；默认只展开到 3 层，避免 400 节点刷屏。
- 勾选「只看可点击」走客户端过滤（避免再多一次 `ui_find`）。
- 选中节点 → 右侧显示 `id / text / desc / class / bounds / center` + 生成的候选选择器 + 唯一性结果。
- 「填入积木」按钮 → 回填。
- **优点**：语义准确，能拿到 `id`；**缺点**：H5/自绘控件常常是一整块 `View`，没有细粒度节点。

### B. 截图叠层点选（所见即所得）

- `screen_capture`（`quality=80`，`maxWidth=1080`）→ 面板里按比例显示。
- 用节点的 `bounds` 在图上叠半透明热区（自己画，不依赖 `annotate`，因为 `annotate` 画的 `#n` 标签会挡内容）。
- 点热区 = 选中对应节点，效果等同 A；点空白 = 提示「此处无节点」，并给「以坐标填入」选项。
- 缩放换算：`deviceX = imgX * (deviceWidth / imgWidth)`，比例从 `screen_capture` 返回的尺寸和 `ui_dump` 的 window bounds 算，不用手填。

### C. 手动坐标

- 在截图上点两下 → 生成 `click(x, y)` 或 `swipe(x1,y1,x2,y2)`。
- 明确标注「坐标会随分辨率/布局变，仅在无常驻节点时使用」。

### 模式选择建议

| 场景 | 用哪个 |
| --- | --- |
| 原生控件、有 id/文案 | A |
| 想确认「点的是不是那个」 | B |
| H5 整块 View、只有坐标可用 | C（配 A 的 bounds 读中心点） |

## 6. 选择器合成（核心）

### 6.1 候选优先级

按「稳定 → 脆弱」排序，逐个试，第一个唯一命中的胜出：

| 序 | 条件组合 | 生成示例 | 稳定性 |
| --- | --- | --- | --- |
| 1 | `id` | `id("com.jingdong.app.mall:id/coupon-left-entry")` | ★★★★★ |
| 2 | `idContains`（用 `idMatches` 去掉包名前缀） | `idMatches(".*coupon-left-entry")` | ★★★★☆ |
| 3 | `text` + `className` | `text("更多任务").className("android.widget.TextView")` | ★★★★ |
| 4 | `text` | `text("更多任务")` | ★★★ |
| 5 | `desc` | `desc("更多任务")` | ★★★ |
| 6 | `textContains` / `descContains` | `textContains("更多任务")` | ★★ |
| 7 | `className` + `depth` + `index` | 不建议写进脚本 | ★ |
| 8 | `bounds` 中心点 | `click(bounds.centerX(), bounds.centerY())` | ☆ |

优先级不是拍脑袋：`id` 来自资源表，改版才变；`text` 会随运营文案变（分享会话里「天天领豆 → 更多任务」就是实例）；`bounds` 换分辨率就废。

### 6.2 唯一性校验

对每个候选，调 `ui_find({selector: 候选, limit: 20})`：

- `count === 1` → 通过。
- `count > 1` → 加约束重试：先加 `className`，再加 `depth`，再加父节点条件（若 A 模式知道父节点）。
- `count === 0` → 不该发生（节点刚从 dump 来）；若发生，调 `ui_explain_selector` 找出第一个失败条件，多半是 `text` 里带了不可见字符或空格差异，转 `textContains` 重试。

> 注意：`ui_find` 是实时查询，校验期间页面若变化会得到不一致结果；校验与 dump 之间插入「窗口签名比对」（见 7.3）。

### 6.3 稳定性评分

给用户一个可读的分值，而不是只给能不能用：

```
score = 100
- id 缺失 → -25；用了 idContains → -8
- 依赖 text → -10；用了 textContains → -6
- 依赖 desc → -6
- 依赖 className → -3
- 依赖 bounds → -40
- count > 1 后加过约束 → -5/次
- 节点 clickable=false（需上溯父节点点击） → -5 并提示
```

`score < 60` 时面板黄字提示「这个选择器换版本/换分辨率可能失效，建议配 `text` 兜底或改用 id」。

### 6.4 生成 AutoJs6 表达式

MCP 的 selector 是 JSON，积木要的是 AutoJs6 表达式，映射表：

| MCP 条件 | AutoJs6 表达式 |
| --- | --- |
| `{text:"x"}` | `text("x")` |
| `{textContains:"x"}` | `textContains("x")` |
| `{textMatches:"re"}` | `textMatches("re")` |
| `{desc:"x"}` | `desc("x")` |
| `{id:"x"}` | `id("x")` |
| `{idMatches:"re"}` | `idMatches("re")` |
| `{className:"x"}` | `className("x")` |
| 多条件 | 链式：`text("更多任务").className("android.widget.TextView")` |
| `boundsContains` | 不进选择器，改写成坐标块 |

积木里 `by` 只能选一个条件，所以：
- 单条件候选 → 直接写 `by` + `value`。
- 多条件候选 → 写主条件到 `by/value`，并在积木的「附加条件」参数（需新增，见 §8）里补 `className`；若不打算加参数，则降级为单条件并在评分里体现。

### 6.5 伪代码

```js
async function synthesize(node, ctx) {
  const cands = [
    { by:'id',            value:node.id,        sel:{id:node.id} },
    { by:'idMatches',     value:'.*' + shortId(node.id), sel:{idMatches:'.*' + shortId(node.id)} },
    { by:'text',          value:node.text, extra:{className:node.className} },
    { by:'text',          value:node.text },
    { by:'desc',          value:node.desc },
    { by:'textContains',  value:node.text },
    { by:'descContains',  value:node.desc }
  ].filter(c => c.value);

  for (const c of cands) {
    const found = await bridge.uiFind(c.sel, 20);
    if (found.count === 1) return { ...c, score: scoreOf(c, found), unique: true };
    if (found.count === 0) {
      const why = await bridge.explain(c.sel);  // 记录第一个失败条件
      c.fail = why.failedCondition;
    }
  }
  return coordinateFallback(node);   // 只给中心点，并明确标注为最弱方案
}
```

## 7. 参数回填映射

| 积木 type | 参数 | 拾取写入 |
| --- | --- | --- |
| `clickNode` | `by`, `value` | 合成结果（唯一命中才写） |
| `longClickNode` | `by`, `value` | 同上 |
| `setTextNode` | `by`, `value` | 拾取「输入框」本身，`text` 参数不动 |
| `nodeTextVar` / `existsVar` | `by`, `value` | 同上 |
| `scrollNode` | `by`, `value`, `dir` | 拾取可滚动节点，`scrollable=true` |
| `coordClick` | `x`, `y` | 取 `center` |
| `swipe` | `x1,y1,x2,y2` | 连点两次（起点、终点），或拾取两个节点中心 |
| `findImage` | — | 不适用，走图像模板 |

回填规则：

1. 写入前 `A6.store.snapshot('拾取控件')`，保证 `Ctrl+Z` 可退。
2. 只改目标积木的目标参数，不动其它字段。
3. 写完后刷新代码面板并**高亮该积木生成的代码行**（复用已有 `highlightCode`），让用户当场看到代码变成了什么。
4. 若用户开着「表达式模式」（P2 功能），写入 `text("x").findOne(3000)` 而不是 `by/value`。

## 8. 需要的代码改动（文件级）

| 文件 | 改动 |
| --- | --- |
| `js/bridge.js` | 新增 `uiFind(selector,limit)`、`explainSelector(selector)`、`screenCapture(opts)`、`currentWindow()`；统一抛 `BridgeError{code,message}` |
| `js/picker.js`（新） | `parseDumpText()`、`parseDumpJson()`、`buildTree()`、`synthesize()`、`scoreOf()`、`renderTree()`、`renderOverlay()`；纯函数可单测 |
| `js/editor.js` | 参数框右侧加 `⌖` 按钮（仅 `by/value`、`x/y` 这类可拾取参数显示）；`pickInto(blockId, paramKey)` |
| `js/app.js` | 装载拾取面板、快捷键、错误提示、真机未连接时禁用 |
| `index.html` | 新增 `#picker` 面板容器（右侧抽屉，不新开页） |
| `css/app.css` | 抽屉、树行、热区、评分徽章样式 |
| `js/catalog.js` | （可选）`clickNode` 等积木增加 `extra` 附加条件参数 |
| `js/runtime.js` | 不改。拾取器是真机专属，模拟器维持原状 |

新增的桥接方法签名：

```js
A6.bridge.uiFind(selector, limit)      // → {count, returned, nodes:[{...bounds, center, selector}]}
A6.bridge.explainSelector(selector)    // → {steps:[{condition,count}], failedCondition, matches, nearMisses}
A6.bridge.screenCapture({format,quality,maxWidth,annotate}) // → {image, width, height, scaled}
A6.bridge.currentWindow()              // → {packageName, activityName, bounds}
```

## 9. 交互与状态机

```
idle ──点⌖──▶ capturing ──▶ loading(dump/find) ──▶ picking(树/叠层)
                                   │                        │
                                   └──失败──▶ error ◀──校验失败──┘
                                                              │
                                                         written ──▶ idle
```

- 入口：参数旁 `⌖`；也可从「真机」页点「抓界面」浏览整棵树（只读）。
- 面板常驻在右侧，可折叠；拾取期间画布不禁用（用户可以先看点别的）。
- 单次拾取只服务一个参数；点另一个 `⌖` 会切换目标，旧目标不自动写。
- `Esc`：退出拾取，不写任何东西。
- 真机断开：面板显示断线提示 + 「重连」，已拾取但未写入的结果保留在面板里，不丢。

## 10. 失败与边界

| 场景 | 现象 | 处理 |
| --- | --- | --- |
| 无障碍未开 | `ui_dump` 报错/空树 | 调 `device_ensure_accessibility`，提示用户在系统设置里开启 |
| 树被截断 | `truncated=true`、`nodes=400` | 面板提示「已截断」，提供「按区域下钻」：在截图上框一块 → `ui_dump` + `boundsContains` 只取该区 |
| `#n` 过期 | `ui_click` 返回 `NODE_REF_STALE` | 自动重新 dump 一次并按 selector 重定位；不重复点击（结果未知时不重放） |
| H5 无节点 | 只有一整块 `View` | 提示「该区域无独立控件」，落到截图坐标模式，并说明脚本会随布局失效 |
| 截图限流 | `RATE_LIMITED` | 按 `retryAfterMs` 退避，面板显示倒计时；不做自动重试风暴 |
| 选择器不唯一 | `count>1` | 逐级加约束；仍不唯一则列出前 5 个候选让用户选，或降级坐标 |
| 文案带空格/换行 | 精确 `text` 匹配不到 | 自动转 `textContains` + 展示去空白后的值，让用户确认 |
| 桥接不可达/CORS | fetch 失败 | 明确报「真机不可用」+ 引导启动 `bridge/mcp-bridge.mjs`，不影响模拟运行 |

## 12. 验收清单

- [ ] 连真机，点 `clickNode` 的 `⌖`，选中「天天领豆」，`by/value` 被写成 `text / 天天领豆`，代码面板对应行高亮。
- [ ] 同一页面有 3 个「立即领取」，拾取时提示「不唯一」，加 `className` 或父节点约束后写入，且 `ui_find` 校验 `count=1`。
- [ ] 拾取一个只有 `bounds` 可用的 H5 区块，面板评分 ≤ 50 并给出黄字警告，用户确认后才写坐标。
- [ ] 拾取过程中在手机上滑动页面，再点「填入」，提示「窗口已变化，请重新抓取」，不写入旧数据。
- [ ] 关闭无障碍服务后点 `⌖`，给出可操作的开启指引，不卡死。
- [ ] `Ctrl+Z` 能撤销一次拾取写入。
- [ ] 未连真机时 `⌖` 置灰，悬浮说明「需要连接真机」，模拟器功能不受影响。

## 13. 风险与取舍

1. **`ui_find` 的自动 selector 用 bounds 钉节点**——看着很准，实则最不稳。方案里明确不用它写脚本，只用它做「此刻能不能点到」的校验。
2. **400 节点/32 层上限**：京东这类页面首屏就超。靠「区域下钻 + 只看可点击 + 懒加载子树」缓解，不做一次性全树渲染。
3. **H5/自绘控件没有语义**：这是平台限制，不是实现问题。方案选择「承认它」，退到坐标并明确标注，而不是假装能识别。
4. **拾取时的页面漂移**：dump 与校验之间页面可能变。用「窗口签名（package+activity+bounds）+ 时间戳」检测，过期就重抓，绝不把旧结果写进脚本。
5. **跨端差异**：拾取器只在连真机时可用；Windows/macOS 上通过 bridge 访问同一台手机，Android 上可直连局域网地址。

**下一步建议**：先做 P0。它不需要截图、不需要评分，只依赖 `ui_dump` + `ui_find` + 回填，能立刻把「手填定位值」这件最烦的事解决掉；P1 的截图叠层是体验优化，可以后置。

## 14. 补充实现：两点取点（swipe，已落地）

单点模式只解决「点哪儿」，滑动要的是「从哪儿到哪儿」，所以单独加了两点模式。

- **入口**：`swipe` 积木的 `x1`/`y1`/`x2`/`y2` 四个参数各有一个 `⌖`，点任一都是同一个两点模式；`coordClick` 仍是单点模式，两者互不影响。
- **取点方式**：截图视图里点两下——第一下落起点、第二下落终点、第三下重新落起点；也可以点两个控件的热区，直接取该控件 `bounds` 的中心（H5 自绘控件没有可点的热区时，仍可点空白处按像素取点）。
- **叠层**：起点/终点各画一个十字标记，带 `① x, y` / `② x, y` 标签；两点齐了用 SVG 连线。线用 `preserveAspectRatio="none"` + `vector-effect="non-scaling-stroke"`，因为截图容器不是等比缩放（1080×2376 塞进抽屉宽度），用 CSS 旋转 div 算角度会失真。
- **详情面板**：显示起点、终点、位移 `dx, dy` 与直线距离；两点齐了「填入起止坐标」才可点，「重取」清空后再取。
- **回填**：写 `params.x1/y1/x2/y2`，`dur` 保持原值；写入前 `snapshot` 可撤销，写完切代码页并选中该积木，生成 `swipe(x1, y1, x2, y2, dur)`。
- **不依赖真机**：两点模式不调 `ui_find` 做选择器校验，离线也能在图上取点；连真机时只是多了热区可点。

实测（Mock 设备 1080×2376）：

| 路径 | 取点 | 结果 |
| --- | --- | --- |
| 点空白两下 (20%,30%) / (70%,70%) | `① 216, 712` `② 756, 1662` | 位移 `540, 950`、距离 1093px；第三下后 `① 539, 237`、连线消失、写入按钮置灰 |
| 点两个控件热区 | `① 240, 160` `② 800, 360` | 与热区中心一致，回填 `swipe(240, 160, 800, 360, 400)` |

两处的坐标偏差都在 1 像素以内，来自百分比换算取整，远小于点击容差。

## 15. 补充实现：选择器体检与批量修好（P3，已落地）

拾取器解决「写进去」，体检解决「写完以后还对不对」。脚本写好后页面会变、文案会改，选择器失效往往要等跑挂才发现；体检把它提前到提交前。

- **入口**：顶栏「⌕ 体检」或 `F8`，弹层面板，不动画布布局。
- **范围**：项目里所有带 `by` + `value` 的积木（主程序 + 各模块，容器积木递归）。已填 `expr` 的积木标「表达式」跳过——代码走的是表达式，`by/value` 已不参与生成；坐标类积木也不在范围内。
- **逐条校验**：`ui_find` 限 20 条，`count=1` 记唯一并给评分（复用拾取器的稳定性评分），`>1` 记重复，`=0` 记未找到。
- **未找到时解释原因**：再调 `ui_explain_selector`，取首个失败条件写进说明（例如「卡在 text」），而不是只说「找不到」。接口不可用时降级为提示文本，不中断整体体检。
- **重复时反推候选**：用命中节点的 `id / text / desc` 走拾取器同一套候选合成，逐个 `ui_find` 验；验到唯一就记为该条的可修方案。候选都不唯一时不给假方案，只提示「用拾取器重拾」。
- **批量修好**：只改有可修方案的条目，写入前统一 `snapshot`（一次撤销回退全部），写完 `save + commit`，代码页同步刷新。
- **报告**：面板摘要「N 个选择器 · 唯一 x · 问题 y · 可修 z」，「复制报告」输出 Markdown 表格（状态 / 积木 / 范围 / 选择器 / 说明），可直接贴进提交说明或 issue。

实测（Mock，10 节点，4 个 `clickNode`）：

| 选择器 | 结果 | 说明 / 动作 |
| --- | --- | --- |
| `id("com.jingdong.app.mall:id/coupon-sign")` | 唯一 | 评分 100 |
| `text("立即领取")` | 2 个 | 命中多个；两条候选都不唯一，不给假方案，提示用拾取器 |
| `textContains("领")` | 4 个 | 可改为 `text("领券中心")`，一键修好后该条变唯一 |
| `text("不存在的按钮")` | 0 个 | 说明「这条选择器在当前页面找不到节点；卡在「text」」 |

修好后摘要变「唯一 2 · 问题 2 · 可修 0」，`Ctrl+Z` 一次回到修好前的 `textContains("领")`。

## 16. 补充实现：真机录制（方案 1，设备侧监听）

### 16.1 为什么不是「IDE 主动录」

MCP 的 49 个工具全是**主动调用**（`ui_dump`、`ui_click`、`screen_capture`…），没有任何事件订阅或事件流；手机侧发生了什么、你点了哪儿，IDE 不可能被动收到。所以录制只能把「监听」下沉到设备：用 `script_run` 推一段监听脚本上去常驻，脚本自己记录事件并落盘，IDE 再去取。这也顺带解决了跨应用录制——脚本在后台，你切到哪个 app 都能记。

### 16.2 数据通路

```
IDE(浏览器/桌面)                    手机(AutoJs6)
  script_run(source, waitForCompletion=false) ──▶ 监听脚本常驻
                                                   ├─ events.observeTouch / onTouch（触摸）
                                                   ├─ events.observeKey（返回 / Home）
                                                   └─ 写 studio-record.jsonl（一行一事件）
  files_read(studio-record.jsonl) ◀──轮询900ms───┘
  script_stop(executionId) ──▶ 停
```

- 用 `files_read` 整读而不是字节偏移：记录文件被 `max` 限在 300 行内，整读最省心，也避开不同版本 `files_read` 的 offset 字段差异；重复行按行数去重。
- `files_read` 的返回形状随版本不同（JSON 里的 `content` / 纯文本），桥接层做了「先 JSON 后纯文本」的兼容。

### 16.3 事件格式

一行一个 JSON：
- `{"type":"start",cap:{...},screen:{w,h},pkg}` —— 自证能力，面板能看到 `observeTouch/onTouch/observeKey` 是否都是 `function`；
- `{"type":"tap",x,y,pkg,node:{text,desc,id,className,bounds,counts}}`；
- `{"type":"swipe",x1,y1,x2,y2,dur}`；
- `{"type":"key",key:"back"}`；
- `{"type":"error",message}` —— 监听注册失败时写，面板直接提示。

`counts` 是设备侧当场按 `id/text/textContains/desc` 各跑一次 `find()` 得到的命中数，所以「这个选择器唯一吗」是**录制当时的真实页面**判定的，比事后复查准。

### 16.4 手势识别与已知边界

触摸监听只给坐标序列，不给按下/抬起的时间戳语义，所以：
- 一段点里位移 < 40px 判**点击**，取最后一点作为落点；
- 位移 ≥ 40px 判**滑动**，起止取首尾点，`dur = 末点时间 - 首点时间`（夹在 200–2000ms）；
- 静默 420ms 视为一段操作结束；
- **长按无法与点击区分**（拿不到按住时长），会被记成点击；需要长按就录完在画布上把它改成 `长按控件`；
- 双指/多指手势不分离，按单指起止点处理。

### 16.5 事件 → 积木

| 事件 | 转成 | 说明 |
| --- | --- | --- |
| tap + 唯一候选 | `clickNode{by,value}` | 优先级 `id` → `text` → `textContains` → `desc` |
| tap 无唯一候选 | `coordClick{x,y}` | 不硬造选择器，直接落坐标 |
| swipe | `swipe{x1,y1,x2,y2,dur}` | dur 夹 200–2000 |
| key | `pressKey{key}` | back / home |

生成时一次 `snapshot`，可整批 `Ctrl+Z`；只插入「新录到」的部分，重复点「生成积木」不会重复插入。

### 16.6 实测（Mock 录制链路）

Mock 的 `script_run(name=a6studio-record)` 返回 `executionId=11, status=running`，`files_read` 每次多给一行，模拟边操作边写：

| 步骤 | 结果 |
| --- | --- |
| 开始录制 | `running=true`、`executionId=11`，面板 5 行（start/tap/tap/swipe/key） |
| 选择器判定 | 点「天天领豆」`id` 命中 1 → 写选择器；点「立即领取」`text` 命中 2 → 退坐标 |
| 生成积木 | `clickNode(by=id,…)`、`coordClick(900,900)`、`swipe(540,1600,540,600,420)`、`pressKey(back)` |
| 生成后代码 | `id("...coupon-sign").findOne(3000)` → `_node1.click()`；`click(900, 900)`；`swipe(...)`；`press("back")` |

真机侧还需在魅族上复验两点：`events.observeTouch/onTouch/observeKey` 是否都为 function，以及触摸坐标是否与 `device.width/height` 同尺度。这两项一旦拿到设备日志就能立刻定位。

### 16.7 鉴权与 CORS（连真机绕不开的两件事）

- **鉴权**：`mcpServers` 里常见 `headers.Authorization: Bearer <token>`。Studio 的设备页有「令牌（可选，只存内存）」，填进去后所有 MCP 请求都带这个头；令牌不写进项目 JSON、不进 localStorage，刷新即清空（密钥不落盘）。
- **CORS**：浏览器直连时，带 `Authorization` 会触发预检，服务端必须在 `Access-Control-Allow-Headers` 里放行 `authorization`，否则浏览器直接报 `Failed to fetch`（与令牌错、服务端挂掉的表现一模一样，很容易误判）。Mock 就踩过这个坑，已放行；`bridge/mcp-bridge.mjs` 一开始就放行。
- **排查顺序**：`Failed to fetch` → 先看服务端 `Access-Control-Allow-Headers` 是否含 `authorization`；再看 token 是否被服务端接受（401 会明确说 `the bearer token is not accepted`）；最后才怀疑地址/端口。

### 16.8 离线录制：导出脚本 + 导入 JSONL（不依赖 MCP）

MCP 通道/配对不通时，录制仍要能用，所以同一份设备脚本提供两条入口：

- **在线**：`script_run` 推上去常驻，IDE 轮询 `files_read`；
- **离线**：「导出脚本」下载 `a6studio-record.js` → 传到手机 → AutoJs6 打开运行 → 按音量下键停止 → 把 `/sdcard/studio-record.jsonl` 拷回电脑 →「导入文件」。

两条入口共用同一个事件格式与转换逻辑，所以转出来的积木完全一致。离线版补了三处：
1. 默认输出改绝对路径 `/sdcard/studio-record.jsonl`，并在 `start` 事件里带上 `path`，导入时面板会显示手机上的文件位置；
2. 开始录制 `toast` 提示，音量下键停止（避免满屏找停止按钮）；
3. 导出文件头部有注释说明用法。

实测（离线导入 5 行 JSONL）：`imported=5`、面板 5 行、`start.path` 正确显示，`生成积木` 得到 `clickNode(by=id, …)`、`coordClick(900,900)`、`swipe(540,1600,540,600,400)`、`pressKey(back)`，代码为 `_node1.click()` / `click(900, 900)` / `swipe(540, 1600, 540, 600, 400)` / `press("back")`；导出脚本内含 `observeTouch`、`volume_down`、`/sdcard/studio-record.jsonl`。
